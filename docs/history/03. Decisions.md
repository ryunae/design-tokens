## 현재 결정

### D-001 저장소·배포 — public 레포 + git 태그 핀 (2026-09-30, private→public 사용자 확정)
- `ryunae/design-tokens`(SSH), 소비는 `"@ryunae/design-tokens": "github:ryunae/design-tokens#vX.Y.Z"`.
- 이유: pnpm(GEO·client-crawling)·npm(review-gen) 양쪽이 먹는 유일한 형태. 태그 핀이라 값이 몰래 바뀌지 않는다. 런타임 의존 0(CSS·woff2 뿐).
- 출처: 설계 §결정 1 · [[600. Developments/reviewgen/11. Changelog]] 2026-09-30 「태그 핀 v1.0.3」(`file:` → `github:` 로 바꿔 맥북프로에서도 설치 가능).
- **갱신(2026-09-30):** 레포는 지금 **public** 이다. payattention-os 브랜치 `claude/design-tokens-consumer` 커밋 `52520991` 「private 이던 때 SSH git 으로 굳어 Vercel 이 못 받았다」 — Vercel 빌드가 받게 하려고 공개로 돌린 것으로 보인다. 그래서 lock 이 codeload tarball 로 풀린다(GEO PR 58). 다시 private 으로 돌리면 Vercel 소비자와 tarball lock 이 깨진다.

### D-002 두 층 — 1층은 패키지, 2층은 각 앱 (2026-09-30)
- 1층: `--ds-` 접두어가 붙은 중립·의미 토큰(값 그대로) + 색상환 hue 5개(hue 만).
- 2층(각 앱): hue 를 누구에게 배정할지, 배경별 명도·채도, 어두운 짝(눈으로 맞춘 대비), 한글 폴백, Tailwind `@theme inline` 배선.
- 접두어 이유: `--card` 자기 참조 무효화, `--muted` 뜻 충돌(배경 vs 글자) — 둘 다 CSS 가 에러를 안 낸다.
- 출처: 설계 §결정 2 · README 「2층 — 여기 없는 것」.

### D-006 소비자 목록은 README 표 하나, 태그 뒤 소비자 전부 올리고 `consumers.mjs` (2026-09-30)
- 「태그는 소비자 전부를 고친 뒤에만」이 README 에 있었는데도 v1.1.1 이 review-gen(v1.0.3)·GEO(v1.1.0)를 두고 달렸다 — 설계 §위험 1번이 그대로 일어났다. 원인: 이 패키지가 공식 프로젝트가 아니라 규칙을 챙길 자리가 없었다.
- 대응: 공식 등록(`lib/` 카테고리) + `scripts/consumers.mjs`(README 표의 각 레포 origin/main 핀을 최신 태그와 비교, 하나라도 다르면 실패).
- **문구 수정(2026-09-30, `80289a2`):** 「소비자를 다 고친 뒤에만 태그」는 지킬 수 없다(소비자는 태그가 있어야 핀을 올린다). 규칙은 **「태그를 달면 같은 작업 안에서 소비자 전부를 올리고 `consumers.mjs` 전부 ok 를 본 뒤 끝낸다」**. 태그 push 훅 차단은 교착이라 쓰지 않는다. v1.2.2 도 client-crawling 만 올린 채 멈춰 한 번 더 깨졌다.

### D-007 소비자 범위 (2026-09-30)
- leels-os · leels-studio 는 자체 디자인 시스템 — 소비자 아님(설계 §비목표).
- **payattention-os 는 소비자다 — 사용자 결정(2026-09-30, 「이미 os 수정되고 있어」).** 설계 §비목표의 「범위 밖」은 client-crawling `7db2c1b` 에서 고쳐졌고, README 표 제외(`c58da25`)는 `9b37fd5` 로 되돌렸다. origin/main 이 v1.1.1 핀 — `consumers.mjs` 4/4 ok.
  - **전환 조건:** 1층의 **이름·구조만** 쓰고 편집국 값(각진 모서리 2/3/4px · 나눔명조 · oklch 잉크 틴트 · letterpress 버튼)은 2층에 남긴다. `globals.css` 452줄의 주석은 브라우저 실측값이다. 1층 값(`--ds-radius-sm` 8px 등)을 그대로 입히면 그 실측이 버려진다. `consumers.mjs` 는 태그만 보고 값을 갈아엎었는지는 못 본다 — 사람이 봐야 한다.

### D-008 사내 앱 화면 기준은 GEO, 「느낌」 값도 1층 토큰으로 (2026-10-27)
- **결정(사용자):** 사내 앱(crawler·reviewgen·adreview·paos)의 화면은 GEO(geomaster) 기준으로 맞춘다. 스택만 맞추는 것이 아니라 **버튼·탭·카드·움직임 모양까지**다. 2026-09-30 crawler React 이전 때 「geo 기준」을 스택만으로 좁혀 적용한 것이 화면이 갈라진 원인이었다(crawler `docs/superpowers/specs/2026-09-30-react-spa-design.md:68`).
- **값은 토큰:** GEO가 화면마다 직접 적던 움직임·조작 높이·hover 밝기를 v1.4.0 1층 토큰으로 올렸다(`--ds-duration*`·`--ds-ease`·`--ds-enter-distance`·`--ds-control-h` 36px·`--ds-glass-hover*`, utilities `.page-enter`·`.motion-colors`·`.glass-panel-hover`). 앱은 이 값을 가져다 쓰고 직접 적지 않는다.
- **접근성이 GEO보다 앞선다:** 글자 대비 4.5:1에 못 미치는 GEO 모양(채운 빨강 위 흰 글자 3.56:1, 흐린 `white/10~45` 글자)은 따라 하지 않는다. 앱들은 테두리형 빨강과 진한 글자를 쓴다. 움직임은 「동작 줄이기」에서 끈다.
- **남은 것(나중에, 사용자 2026-10-27):** GEO 자체의 토큰화, GEO 채운 빨강 대비, GEO 흐린 글자 207곳.
- 적용: crawler PR 84·85·86, adreview PR 8·9, reviewgen PR 36·37·38, paos PR 554·555·556.

### D-009 채움용 보라는 따로 — `--ds-primary-solid` (2026-10-27)
- **문제:** `--ds-primary`(L67%) 위 흰 글자(`--ds-primary-foreground`) 대비가 **4.06:1**이다. 주 단추·지금 탭·선택 표시가 다섯 앱 모두 4.5:1에 못 미친다.
- **하나로 고치지 않은 이유:** primary 자체를 어둡게 하면 어두운 바탕 위 보라 **글자**(링크·현재 메뉴, 지금 4.7:1)가 떨어진다(L60%에서 3.38:1). 바탕용과 글자용은 요구가 반대라서 둘로 나눴다.
- **결정(사용자 승인):** 바탕용 `--ds-primary-solid` L62%(흰 글자 5.15:1)와 `--ds-primary-solid-border`를 둔다. 글자·테두리 보라는 `--ds-primary` 그대로 쓴다. v1.5.0, 소비자는 「보라 바탕 + 흰 글자」 자리만 solid로 바꾼다.

### D-010 그라데이션 단추의 자주 끝도 채움용 — `--ds-accent-solid` (2026-10-27)
- **문제:** 보라→자주 그라데이션 바탕에 흰 글자인 단추(paos 주 Button, reviewgen·GEO·crawler 로그인 단추)는 자주 끝(`--ds-accent` L65%)이 3.38:1이다. D-009의 primary-solid만으로는 반쪽만 고쳐진다.
- **결정(사용자 승인):** `--ds-accent-solid` L50%(흰 글자 5.13:1)를 둔다. 글자가 얹히는 그라데이션은 `from --ds-primary-solid to --ds-accent-solid`로 바꾸고, 글자 없는 장식(로고 상자·막대·글자 그라데이션)은 그대로 둔다. v1.6.0.
